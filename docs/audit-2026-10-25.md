## 2. The one real defect: two verdicts are unconditional

`runScenario` branches on `scenario.layer` **before** looking at any evidence:

```ts
if (scenario.layer === "disclosure") { ... return finalize({ code: "UndisclosedLink", status: "FLAGGED" }) }
if (scenario.layer === "sentinel")   { ... return finalize({ code: "DelegatecallDetected", status: "FLAGGED" }) }
```

Probe: pass scenario 10 a challenge with `score: 0` and `linkCount: 0`.

```
risk=0, links=0 -> FLAGGED UndisclosedLink
message: "An undisclosed funding path connects the proposer to the GrowthLabs deployer.
          Noisy-OR risk 0.00 across 0 links; the proposal is flagged."
```

The verdict does not move, and the message contradicts itself.

Same for scenario 06: the trace fixture *does* contain a `DELEGATECALL` child and a matching
`flags[0].code`, but the executor never reads the file. `traceRef` is a filename string; the
verdict comes from `scenario.layer`. The `linkIds: ["l1".."l4"]` in scenario 10's context are
likewise never read.

### Why this matters more than a cosmetic bug

Scorecard rows `S6` and `S10` assert `actual == expected`, where `expected` is hand-written and
`actual` is an unconditional constant. **Those two rows can never fail.** They are tautologies
counted inside the 25 PASS. Everything else in the scorecard is falsifiable; these two are not.

This is the exact failure mode the project is built to expose — a check that looks like evidence
but cannot be contradicted. It is not disclosed in the README, which says only that the trace is
a fixture and disclosure verification is simulated.

### Suggested fix (behaviour-preserving for the demo)

Gate each branch on its own evidence, and fall through to the executor checks when the evidence
does not support a flag:

- **Sentinel:** parse `sentinel-trace-06.json`, walk the call tree for `type === "DELEGATECALL"`
  (or a non-empty `flags` array). Flag only if found; otherwise continue to the executor path,
  which will reject the `upgradeToAndCall` with `SelectorNotAuthorized`.
- **Disclosure:** flag only when `challenge.score >= challenge.threshold`; otherwise continue.

Both scenarios still return `FLAGGED` on the current fixtures, so `demo-script.md` stays valid —
but the rows become capable of failing.

## 3. Secondary findings

1. **The GitHub repo is empty.** `BeastAyyG/CODE_TANTRAFEST` (private) has one commit and one
   file, `README.md` (1 KB). The local repo has 2 commits and **no `origin` remote**. None of this
   code is on GitHub. If the submission link is that URL, the submission is a README.
2. **Fabricated value inside revert data.** In `checkSingle`, the `upgradeTo` branch encodes
   `args: [call.target, match.codeHash, ZERO_HASH]` — a zero hash stands in for the "actual"
   implementation code hash. The human text is right; the payload carries a placeholder where a
   measured value belongs.
3. **`transferBudget` ignores approvals.** The cumulative post-condition sums only
   `ERC20_TRANSFER` rules, so allowance is not counted against the budget. Arguably correct
   (an allowance is not a spend), but it is undocumented.

## 4. Bottom line

The honest-labelling discipline in the README is real, and it survives probing: the numbers are
computed, the proofs verify in the browser, the executor enforces rules rather than replaying a
table. Two of the eleven arena verdicts, and therefore two of the twenty-five PASS rows, are
constants dressed as checks. Fix those two, push the repo, and the gap between what this claims
and what it proves is essentially closed for the TypeScript layer — with the nine on-chain
properties still correctly amber.
