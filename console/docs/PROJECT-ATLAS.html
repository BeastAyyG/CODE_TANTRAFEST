AegisDAO IntentLock · whole-project atlas

Two layers.
One binding problem.

A chain layer that can enforce a proposal commitment, and an experience layer that makes the gap between what a proposal said and what it would execute impossible to miss. They were built in parallel. They are not yet merged.

system atlas A: chain + intelligence · main B: judge experience · b/judge-mode no common ancestor 57 B tests
01 / COMMITEvidence and disclosure, not just calldata

A single commitment over rules, calldata, evidence root, disclosure hash and version. Binding a vote to bytes is table stakes; binding the evidence and the conflicts is the addition.

02 / COMPREHENDMake the description gap legible

Source-linked claims, a strict validator, a human resolution loop, a recursive decoder and a deterministic report that puts the proposal quote beside the decoded call.

03 / REFUSERefuse uncommitted shapes; verify code identity

No hidden multicall child, no unapproved upgrade, no stale version, no code swapped after approval. The executor is the gate; Sentinel is early warning.

Seam 1 · commitment

A and B compute different commitments from different preimages. A binds a typehash and version hash; B binds a proposal key, evidence root and disclosure. This is the first thing the integration must reconcile.

Seam 2 · executor

A's IntentLockExecutor.execute takes rules and actions; B's reference execute takes a three-argument bundle. A deployed call needs an adapter, not a rename.

Seam 3 · evidence

A's evidence store and B's evidence manifest are independent. The roots will not match until one store feeds both.

Seam 4 · truth

A's scorecard says 11/11 scenarios pass. B's scorecard says 9 properties are TEST_REQUIRED because B is not wired to A. Both are true in their own tree; the combined truth is the integration work.

04 / Chain layer · Person A

The refusal engine.

main · 55c636a

The chain layer does not decide whether a proposal is wise. It decides whether a transaction is the transaction the vote committed to. The interesting property is refusal: an unapproved selector, a hidden multicall child, a stale version or an implementation whose code hash changed must not execute.

Governor lifecycle

DisclosurePending→ VotingOpen→ Passed→ Queued→ Executed
Draft · never assigned Defeated Halted Cancelled

submitProposal writes DisclosurePending directly; a draft exists only in the registry. syncFromExecutor is a manual pull nothing calls — the governor can remain Queued while the executor is Executed or Halted.

Executor gate

01 · recomputeactionsHash, intentHash, commitment from chain id, executor and fields.
02 · stateMust be Queued; otherwise ProposalNotInState.
03 · timelockblock.timestamp ≥ eta; otherwise TimelockNotExpired.
04 · versionRegistry latest must equal the submitted version hash; otherwise VersionSuperseded.
05 · rulesTop-level action count must equal rule count; each action is enforced exactly.
06 · effects firstState is written before interactions; a re-entrant recipient cannot execute twice.
07 · postconditionsAllowance ceiling only. Balance-drain and native-value cap are not implemented.
Honest edges
· A commitment mismatch surfaces as ProposalNotInState(Queued, Empty), not CommitmentMismatch.
· There is no native-value check; value is bound in actionsHash but no ceiling exists.
· _postConditionChecks is an allowance check; the comment about balance decrease is not code.
· castVote, Defeated, syncFromExecutor, cancelProposal and returnBond have no test in A's checked-in suite.
CodeHashMismatch uses keccak256("") as observed code hashonly call · no delegatecall path

Action kinds

ERC20_TRANSFER · 0

Exact target, selector, recipient and amount ceiling. Calldata length 68.

ERC20_APPROVE · 1

Exact spender, bounded ceiling, explicit unlimited-approval guard.

PARAM_SET · 2

Selector plus first uint256 within maxAmount; semantic matching is out of scope.

UPGRADE · 3

Implementation address and extcodehash check. Code swapped after the vote reverts.

OWNERSHIP_TRANSFER · 4

Exact new owner; hidden ownership inside a multicall fails the child rule.

MULTICALL · 5

Depth < 2, child count matches, every child consumes its own committed rule.

Error surface A emits 43 selectors across four contracts (12 from ActionDecoder). B's report maps 17 definitions. Only CommitmentMismatch and ExceedsSpendLimit currently share a name and selector; SelectorNotAllowed is not SelectorNotAuthorized, and UnauthorizedRecipient(address,address) is not B's one-argument form. This is an integration task, not a UI detail.

Sentinel · early warning, not the gate

Simulate

Snapshot state, execute the queued commitment through the real executor, capture, then revert.

Diff

Balances, allowances, owner/admin, EIP-1967 implementation and code hash, plus routing.

Scan

Static bytecode scan for DELEGATECALL, CALLCODE, SELFDESTRUCT.

Halt

Guardian submits the report hash; halt only, never execute or edit.

Sentinel observes a sandbox, not the block that will run. It is useful exactly because the executor remains the only guarantee.

05 / Intelligence bridge · Person A

Turning documents
into a defensible rule set.

main · intelligence/

Person A's intelligence modules are the bridge between source documents and the chain. They are real code, but two of them disagree with the executor they are meant to feed. That is the most important integration finding in the project.

evidence.ts

Content-addressed store, sorted-pair Merkle root, proofs, and a verifySource that re-hashes the exact file and bounds the quoted span. An empty tree is an explicit unknown, not a zero hash.

realMerkle

chain.ts

Four sequential stages with thresholds in one CONFIG. Missing input yields UNKNOWN, never PASS. Execution is a hard gate: reverted, flagged or halted → RED; pending with a Sentinel violation → RED; not submitted → UNKNOWN.

realUNKNOWN-never-PASS

graph.ts

Simulated wallets, four link types, noisy-OR, disclosed damping and an evidence-bound challenge payload. Like B's graph, it is a risk signal over fake transfers, not a finding of wrongdoing.

simulated datareal math

ai-draft.ts

Produces an IntentSpec; ambiguous questions stay in unresolved[] rather than being guessed. It has heuristic and LLM-shaped paths, but no live model is required to explain the demo.

advisoryunresolved

intent-bridge.ts · divergence 1

It computes intentHash = keccak256(canonical JSON). The executor computes keccak256(abi.encode(rules)). The bridge refuses to run while unresolved[] is non-empty, but once it runs, the hash it produces is not the executor's hash.

real bugbreaks P1

intent-bridge.ts · divergence 2

It reports childCount = children.length for MULTICALL but encodes an empty inner bytes[]. A bridged multicall can never match an on-chain rule set.

real bugbreaks nested enforcement
The bridge is not just plumbing The chain layer and the console agree on the concept of a commitment but not on its preimage, error vocabulary, action encoding or graph constants. Fixing these is the first real integration milestone — before wiring any button to a contract.

10 / Positioning

Why this is not
just another Governor.

the precise claim

Binding a vote to calldata is already solved by Compound and OpenZeppelin Governors. The honest gap is comprehension, evidence, conflicts and code identity at execution. Say that before a judge says it for you.

SystemIt already hasIt leaves open
Compound / OZ GovernorProposal id = hash of encoded callsDescription is a separate string; no evidence or disclosure commitment
Tally / Tenderly / OZ DefenderDecoding, simulation, state diffsAdvisory display; the executor does not consult it
Zodiac RolesStanding calldata permissions at executionA policy, not a per-proposal commitment
IntentLockPer-proposal commitment + refusal semanticsEvidence and disclosure are in the commitment; the report makes the gap legible

Say these limits out loud

A vote that honestly authorizes something bad still executes. We bind intent to action; we do not judge whether the intent is wise.
Self-authored evidence can be internally consistent. The Merkle root proves the documents did not change after signing; it does not prove they are true.
A compromised governor or executor invalidates the guarantee. Commitment immutability is a security property, not a nicety.
The informed-vote receipt raises the cost of voting blind. It does not stop a delegate voting against their mandate with their eyes open.

The fuller prior-art review and build direction are in person-a-direction.md.
