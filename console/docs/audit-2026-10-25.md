## 2. The one real defect: two verdicts were unconditional — **FIXED**

`runScenario` branched on `scenario.layer` **before** looking at any evidence:

```ts
if (scenario.layer === "disclosure") { ... return finalize({ code: "UndisclosedLink", status: "FLAGGED" }) }
if (scenario.layer === "sentinel")   { ... return finalize({ code: "DelegatecallDetected", status: "FLAGGED" }) }
```

Probe: pass scenario 10 a challenge with `score: 0` and `linkCount: 0`.

```
risk=0, links=0 -> FLAGGED UndisclosedLink
message: "An undisclosed funding path connects the proposer to the GrowthLabs deployer.
          Noisy-OR risk 0.00 across 0 links; the proposal is flagged."
```

The verdict did not move, and the message contradicted itself.

### Why this mattered more than a cosmetic bug

Scorecard rows `S6` and `S10` asserted `actual == expected`, where `expected` is hand-written and
`actual` was an unconditional constant. **Those two rows could never fail.** They were tautologies
counted inside the 25 PASS. Everything else in the scorecard is falsifiable; these two were not.

### The fix

Each branch is now gated on its own evidence, and falls through when the evidence does not
support a flag:

- **Sentinel** — `traceFlagsDelegatecall()` walks `sentinel-trace-06.json`'s call tree for a
  `DELEGATECALL` node (falling back to its explicit `flags` array). No trace, or no
  `DELEGATECALL` in it, means no flag; the scenario continues to the executor checks, which
  reject the `upgradeToAndCall` with `SelectorNotAuthorized`.
- **Disclosure** — the flag requires `challenge.score >= challenge.threshold`. Below it, the
  layer raises no objection and returns a truthful message instead of a flag.

### Verification

| Case | Before | After |
| :--- | :--- | :--- |
| Scenario 10, real challenge (0.88 ≥ 0.65) | FLAGGED | FLAGGED (unchanged) |
| Scenario 10, challenge at risk 0.00 / 0 links | FLAGGED, self-contradictory message | PASSED, "not substantiated" message |
| Scenario 06, real trace | FLAGGED | FLAGGED (unchanged) |
| Scenario 06, trace absent | FLAGGED | falls through → REJECTED `SelectorNotAuthorized` |

All eleven baseline verdicts are unchanged, so `demo-script.md` remains valid. Test count went
49 → 51; scorecard stays 34 entries at 25 PASS / 0 FAIL / 9 TEST_REQUIRED.

**Proof the rows can now fail:** temporarily reverting either gate to a constant produces
`S6 FAIL — a missing trace must not assert a delegatecall` and
`S10 FAIL — a sub-threshold graph must not raise a disclosure flag`, with the scorecard exiting
non-zero. The rows are now falsifiable, which is the point.

## 3. Secondary findings

1. **The GitHub repo was empty — now pushed.** `BeastAyyG/CODE_TANTRAFEST` (private) held one
   commit and one file, `README.md` (1 KB); the local repo had 2 commits and no `origin`. The
   full tree (87 files) is now on `main`, verified against the remote via the Git Data API rather
   than the push exit code.
2. **Fabricated value inside revert data — fixed.** `checkSingle`'s `upgradeTo` branch encoded
   `args: [call.target, match.codeHash, ZERO_HASH]`, a zero hash standing in for the "actual"
   implementation code hash. The model deploys nothing, so no address holds bytecode — but that
   is a fact worth *stating*, not a zero worth *emitting*. It now reports `keccak256("")`, the
   EIP-1052 `extcodehash` of an account with no code, and attaches a note saying so. A test
   asserts the payload contains that value, which the old zero could never satisfy.
3. **`transferBudget` ignores approvals — documented.** The cumulative post-condition sums only
   `ERC20_TRANSFER` rules. This is deliberate: an `approve` ceiling is a permission, already
   bounded by `ExceedsAllowance`, and counting it would double-count the same USDC. The reasoning
   now lives in a comment above `transferBudget` and the run step reads
   "… committed transfer budget (allowances excluded)".

## 4. Bottom line

The honest-labelling discipline in the README is real, and it survives probing: the numbers are
computed, the proofs verify in the browser, the executor enforces rules rather than replaying a
table. The two verdicts that were constants dressed as checks are now derived from the trace and
the graph, and both rows fail when that derivation is removed — so the scorecard's 25 PASS are
all falsifiable, with the nine on-chain properties still correctly amber.

Remaining gaps are the ones the README already declares: no Solidity, no chain, simulated wallet
data, pre-baked extraction. All three secondary findings are now closed.
